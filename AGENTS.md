# AI agent instructions — Math Master (`math_game_2`)

Guidance for AI coding agents (Claude Code, GitHub Copilot, …) working in this
repository. `CLAUDE.md` imports this file, so keep it as the single source of
truth.

## What this is

A Flutter math-practice game for **2nd-grade children** ("Kids Math Practice |
Biatec" in stores, package `math_game_2`, Android id `io.biatec.math_master`).
Players answer timed +, −, ×, ÷ questions (numbers up to 100 by default; a
parent can choose other ranges and drills), earn coins and gems, buy button
styles and care for a pet. Everything is stored **locally on the device**
(`shared_preferences`); there is no backend and no network code.

Because the audience is young children, keep copy friendly and simple, never
add ads, tracking, analytics or network calls without explicit approval, and
keep the privacy policy (`docs/privacy-policy/*.md`) accurate if data handling
changes.

## Commands

```bash
flutter pub get
flutter analyze            # must report "No issues found!"
flutter test               # all tests must pass
flutter test test/question_generator_test.dart   # single file
flutter run -d chrome      # run locally (web) — needs platform folders, see below
```

- CI (`.github/workflows/ci.yml`) runs `flutter analyze` and `flutter test`
  with Flutter **3.50.0**, then builds APK/AAB and web.
- **Formatting is not enforced by CI.** The local Dart formatter may be newer
  than the one the code was written with and would reformat many files. Do
  **not** run `dart format` on existing files — it rewrites them wholesale.
  Match the surrounding style by hand; only format brand-new files.
- Platform folders (`android/`, `ios/`, `web/`, …) are **git-ignored** and
  generated in CI by `flutter create`. Never commit them. To create them
  locally, use the same command as CI:
  `flutter create --platforms=android,ios,web --org io.biatec --project-name math_master .`
  (add `windows` to the list to run as a Windows desktop app; CI and the release
  workflow build it with `flutter build windows --release` and brand the
  runner via the "Apply Windows app metadata" step). Native config changes (manifest, Gradle, Info.plist)
  must be made in the Python patch steps inside the workflows, not in files.
- **App icons**: `flutter create` fills the platform folders with the Flutter
  logo; `flutter_launcher_icons` replaces it (Android/iOS config in
  `pubspec.yaml`, web and Windows in `tool/icons/*.yaml`) and
  `tool/check_launcher_icons.py` fails the build if a template icon is left.
  **Never** add a root file named `flutter_launcher_icons-<name>.yaml`: it is a
  "flavor" and makes the tool skip the `pubspec.yaml` config.
- **Store screenshots** are generated by
  `flutter test tool/screenshots/store_screenshots_test.dart` (English) or
  `python tool/screenshots/generate_all.py` (every language; see
  `docs/SCREENSHOTS.md`). Their captions are in
  `tool/screenshots/captions.dart`: add a language there (and rebuild the fonts
  with `tool/screenshots/subset_fonts.py`) when you add a supported language.
  When a screen changes noticeably, regenerate them and commit
  `docs/screenshots/en/play-phone/` and the feature graphic.

## Architecture

```
lib/
  main.dart          app bootstrap; MathGameApp(State) owns locale + theme mode
  theme.dart         AppTheme light/dark ThemeData
  l10n/app_strings.dart   ALL user-facing text, every supported language
  models/            plain data: Question, GameConfig/ChallengeDuration,
                     OperationType, PracticeSettings (range, crossing, drills,
                     tables), ScoreEntry, PlayerProfile, Pet, BackgroundStyle
  logic/             pure Dart, no Flutter imports, fully unit tested
    question_generator.dart  questions + 6 answer cards (mistake-based distractors)
    scoring.dart             points per answer by response time
    game_controller.dart     a game session; spaced repetition, gem streak, stats
    coins.dart               coins earned per game
    gems.dart                gem streak length and coin value
    parental_gate.dart       the (2^a + b×c) mod 1000 grown-ups question
    history_stats.dart       aggregated history statistics for parents
  services/          persistence + platform: PlayerService, LeaderboardService,
                     CoinService (CoinWallet incl. gems), ParentalSettingsService,
                     AudioService, NotificationService, ThemeService
  screens/           StatefulWidget screens; navigation via Navigator.push +
                     MaterialPageRoute (no router package, no state library)
  widgets/           AnswerCard, Fireworks, pet widgets, PracticeSettingsForm
```

Key conventions:

- **Notifications** (pet reminders) only exist on Android and iOS; on the web and
  on desktop `NotificationService` is a no-op.
- **UI imports**: Flutter 3.50 deprecates `package:flutter/material.dart`.
  Import `package:material_ui/material_ui.dart` (and `cupertino_ui` only for
  Cupertino localizations) instead.
- **State management** is plain `StatefulWidget` + `setState`. Screens create
  their services directly (`final _service = PlayerService();`). Don't introduce
  Provider/Riverpod/Bloc or a router unless asked.
- **Keep `lib/logic/` Flutter-free** so it stays unit-testable. Inject `Random`
  (e.g. `QuestionGenerator(random: Random(42))`) for deterministic tests.
- **Persistence** uses JSON strings in `shared_preferences` under **versioned
  keys** (`players_v1`, `history_v2`, `wallets_v1`, `theme_mode_v1`,
  `audio_muted_v1`, `practice_settings_v1`, `onboarding_done_v1`, …).
  `fromJson` must tolerate missing/old fields with
  defaults. If you change a stored format incompatibly, bump the key suffix and
  migrate or default gracefully — never crash on old data.
- Players are identified by **name**. Wallets (`CoinService`) and history
  (`ScoreEntry.name`) are keyed by name.
- Enums are persisted by stable string (`OperationType.storageKey`, `PetType.id`)
  — except `ChallengeDuration`, which is stored by `index`, so **only append** new
  values to that enum.
- Leaderboards group games by `ScoreEntry.gameTypeKey` (duration + sorted
  operations + `modeKey`). `modeKey` describes non-classic difficulty (range,
  crossing, drills, tables) and is **empty for the classic mode**, so old games
  keep their leaderboards. Never let different modes share a leaderboard or the
  top score that decides coins.
- Practice settings (`PracticeSettings`) are chosen in the parental control
  panel and stored per player by name. Players without their own settings use
  the "template" (first-run setup or "apply to all players"); editing one
  player never changes another. **Defaults equal the classic game** except
  that `÷ 1` is no longer asked (divisors come from tables `2..10`). The first-run setup is shown
  once on a fresh install (`onboarding_done_v1`); installs that already have
  players skip it.

## Game rules (keep code, README, in-app Guide and tests in sync)

- Default (classic) mode: operands and answers stay in `0..100`; subtraction
  is never negative; multiplication factors are `2..10`. Parents can pick
  `NumberRange` within 5/10/20/100/1000 for + and −, a `CrossingMode`
  (none/mixed/only, carry or borrow in the units column; also tens within 1000),
  the multiplication tables, and `Drill`s (±1/2, doubles/halves, near doubles,
  pairs to 10/100, bridging through ten, missing number).
- Division always divides evenly; the divisor is an enabled table (`2..10`) and
  the quotient is in `1..10` (`QuestionGenerator.maxDivisionValue = 10`), so the
  dividend is at most 100.
- Gems (`Gems`): every 5 correct answers in a row (slow-but-correct counts)
  earns 1 gem; a wrong answer resets the streak; the streak does not carry over
  between games. The shop buys gems back at 10 coins each.
- Parental gate: `(2^a + b × c) mod 1000`, `a ∈ 5..20`, `b, c ∈ 10000..99999`;
  a wrong answer shows a new problem.
- Changing a pet's type keeps its feeding/enjoyment values and timestamps;
  re-adding an existing player name keeps the existing profile and pet.
- Every question has exactly `QuestionGenerator.optionCount = 6` distinct,
  non-negative answer cards.
- Scoring (`Scoring`): `<1 s` → 3 pts; `1–10 s` → linear 3→1; `>10 s` or wrong →
  −1.
- A missed question is re-asked as the 3rd question after the miss (2 fresh
  questions in between) — `GameController`'s `reaskAfter` constructor
  parameter, default `3`, counts `nextQuestion()` calls until it returns.
- Shop (`BackgroundStyle`): 20 styles on offer; prices are deterministic per
  style index — every fifth costs `budgetPrice = 50`, the rest 100–1000 in tens;
  at least `minimumBudgetStyles = 4` budget styles are always shown.
- Coins (`Coins.maxForDuration`): 1 min → 20, 2 min → 50, 5 min → 150, linear by
  score vs. the category's top score (for a category nobody has played yet: the
  best score of that challenge length, so new modes cannot farm the full
  reward). `CoinService.addReward` pays coins and gems in one save.
- Pets: food −100/day, fun −20/day; feed = 20 coins/+30 food, toy = 100 coins/+50
  fun; hungry/sad below 20.

When you change a rule, update in the same change: the code, its unit test,
`README.md`, the in-app Guide strings (`doc*Title`/`doc*Body` keys) in **all**
languages, and `docs/description/*.md` if the store text mentions it.

## Localization

`lib/l10n/app_strings.dart` is a hand-written map — **not** `flutter gen-l10n`/ARB.

- Supported: `cs de en es fr ja ko ru sk tr zh` (`AppStrings.supportedLocales`).
- Adding a string: add the key to **every** language map in `_localizedValues`
  (English is the fallback, but missing translations are a bug), then add a
  getter (`String get foo => _text('foo');`) or a formatter using
  `_format('foo', {'name': name})` with `{name}` placeholders.
- Plurals are handled by helpers (`coinWord`, `_usesFewSlavicForm`,
  `_usesRussianOneForm`, …) — extend them for count-dependent text.
- Use it in widgets via `context.strings.foo`. Never hard-code user-facing text.
- Per-language docs live in `docs/description/<code>.md` (store listing) and
  `docs/privacy-policy/<code>.md` (bundled as an asset; `index.md` is English).
- Use `/add-string` or `/add-language` (in `.claude/commands/`) for these tasks.

## Testing

- Tests live in `test/` (flat, `<subject>_test.dart`). Add/extend tests for every
  behaviour change; logic changes need unit tests, UI changes need widget tests.
- Widget/service tests must call `SharedPreferences.setMockInitialValues({})` in
  `setUp`.
- Widget tests wrap screens in `MaterialApp` with
  `AppStrings.localizationsDelegates` / `AppStrings.supportedLocales`; set
  `tester.view.physicalSize` for layout tests and reset in `addTearDown`.
- `GameScreen` runs a periodic timer: end such tests with
  `await tester.pumpWidget(const SizedBox());` so the timer is disposed.
- Randomised logic: loop a few hundred iterations with a seeded `Random` and
  assert invariants (ranges, distinctness, correctness).

## Git & PR workflow

- Branch from `main` (`feat/…`, `fix/…`, `chore/…`, `docs/…`); conventional
  commit messages (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- Before committing: `flutter analyze` clean and `flutter test` green.
- Line endings are LF (enforced by `.gitattributes`); don't commit CRLF churn.
- Releases: push a `vX.Y.Z` tag → `release.yml` builds a signed AAB and uploads
  it to Google Play internal testing, and builds a Windows zip attached to the
  GitHub Release once the Play upload succeeded (see
  `docs/GOOGLE_PLAY_RELEASE.md`). In CI the version *name* in `pubspec.yaml` is
  overwritten from the tag and the build number (Play version code) from the
  workflow run (`10000000 + run number * 10 + attempt - 1`), so don't predict it
  from the tag. Only the newest plain `vX.Y.Z` tag can be released.
- Never commit signing material (`*.jks`, `key.properties`) or secrets.
- Use `/ship` for the branch → PR → review → fix → merge loop.
